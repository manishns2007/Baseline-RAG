# Baseline Legal RAG — POCSO Act (Phase 1)

A clean, linear **Retriever → LLM → Answer** pipeline for answering legal questions
about the Protection of Children from Sexual Offences (POCSO) Act, 2012, with
section-level citations. This is Phase 1 of a multi-phase research project; it
contains no orchestration layer and is designed as a stable reference baseline.

---

## Stack

| Component | Library / Tool |
|---|---|
| Embeddings | `sentence-transformers` — `BAAI/bge-base-en-v1.5` |
| Vector store | `chromadb` — local persistent client |
| Sparse retrieval | `rank_bm25` — BM25Okapi |
| LLM | Ollama — `llama3.1:8b` at `http://localhost:11434` |
| Python | 3.11+ |

---

## Quick Start

### 1. Install dependencies

```bash
pip install -r requirements.txt
```

### 2. Supply the POCSO Act source text

Place the plain-text copy of the Act at:

```
data/pocso_act.txt
```

> Plain `.txt` only (UTF-8). If you have a PDF, extract the text first using a
> tool of your choice and save it there.  
> Source: <https://legislative.gov.in/sites/default/files/A2012-32.pdf>

### 3. Parse and sanity-check section boundaries

```bash
python chunker.py
```

This prints every line detected as a section header via `debug_chunk_boundaries()`.
**Verify the output against the first ~10 sections of your source file before
proceeding.** If the list looks wrong, check the blank-line formatting in your
source text and adjust `_SECTION_RE` in `chunker.py` if needed.

After verification, `chunker.py` saves `data/chunks.json`.

### 4. Build the retrieval indices

```bash
python index_builder.py
```

Builds:
- `chroma_db/` — dense vector index (Chroma persistent)
- `indices/bm25_index.pkl` — BM25 sparse index
- `indices/chunk_map.json` — chunk ID → text lookup

### 5. Ask a question

```bash
python pipeline.py "What is the punishment for aggravated penetrative sexual assault under POCSO?"
```

## Output format

`answer_question()` returns:

```python
{
    "answer":               str,         # LLM answer with [Section X] inline citations
    "cited_sections":       List[str],   # unique section numbers extracted from answer
    "retrieved_chunk_ids":  List[str],   # chunk IDs passed to the LLM
    "latency_seconds":      float,
    "is_refusal":           bool,        # True if LLM returned the out-of-scope phrase
}
```

## Evaluation

Run the scaffold test set manually or in a loop:

```python
import json
from pipeline import answer_question

questions = json.load(open("eval/test_questions.json"))
for q in questions:
    result = answer_question(q["question"])
    print(q["id"], "|", result["cited_sections"], "|", result["is_refusal"])
```

## Notes

- **Re-indexing**: `python index_builder.py` always drops and recreates the Chroma
  collection, so it is safe to re-run after updating `pocso_act.txt`.
- **Ollama**: Only `generator.py` and `pipeline.py` require Ollama to be running.
  `chunker.py` and `index_builder.py` can be used offline.
- **Chunk size floor**: Short definitional sections (e.g. Section 2 sub-definitions)
  may produce small chunks that under-retrieve against longer sections in dense
  search. Flag this if it appears during eval; no code change needed for Phase 1.
